> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Members send one photo at a time, from the gallery or the camera, with an optional caption, in direct and group chats.
Photos are end-to-end encrypted, travel through the mesh as generic chunked blobs and are kept on the phone as encrypted
originals. Recipients see a thumbnail at once, download the full photo automatically or on tap, open it full screen with
zoom, and can save it to the gallery. **Done when:** a 20 MB blob goes through the mesh while a node is down.

**Architecture:**
- *Nodes:* a blob is announced by a signed `BLOB_META` record (size, 256 KiB chunk size, SHA-256 of every chunk, readers,
  expiry). It replicates like any record. The chunk bytes don't go through the oplog: they are files under
  `<data_dir>/blobs/`, uploaded by the author with `blob.put`, verified against the signed hashes, pulled by other nodes in
  the background over the existing peer session (new frames `PeerBlobGet`/`PeerBlobChunk`, 2 MB/s), and proxied on demand when
  a reader asks a node that doesn't have a chunk yet. A reader that has the whole blob publishes a signed `BLOB_FETCHED`
  record; when every reader has fetched it (or it expires), every node deletes it and keeps a tombstone.
- *App:* a photo is re-encoded (JPEG, ≤ 2560 px, no EXIF), encrypted with a fresh key (Tink AES-256-GCM-HKDF streaming),
  and the **ciphertext file is the phone's encrypted original**. The message and its outbox row are saved at once, the
  outbox row held; `MediaTransfers` (a session worker like `Outbox`) uploads the chunks, then releases the envelope, whose
  `DataMessage` carries an `Attachment` (blob key, key, digest, size, dimensions, a tiny thumbnail). Receivers store the
  attachment, download according to the auto-download setting, verify the digest, and acknowledge with `BLOB_FETCHED`.
  Plaintext exists only in memory (and in the gallery when the user saves).

**Decisions (made by the planner; Task 12 records them as D44–D48 in `docs/00-decisions.md`):**
- **D44 Blob identity and integrity:** the blob key is the record key of its `BLOB_META` (`author‖id`, 32 bytes), so nobody
  can pre-empt someone else's blob. `BLOB_META` lists the SHA-256 of every 256 KiB chunk; nodes verify every chunk, from
  a client or from a peer, before storing it. Limits (node config `[limits]`): `max_blob` 100 MiB, `user_quota` 2 GiB of
  live blobs per author (P13); over the limit → `STATUS_QUOTA`. Readers 1–100, never the author; expiry ≤ 31 days after
  `created_ms`.
- **D45 Blob lifetime and transfer between nodes:** a reader publishes `BLOB_FETCHED` (new record type 14) after a verified
  download. When every reader has one, or the blob expires, every node deletes the blob (rows, record, files) and keeps a
  tombstone until expiry + 1 day, so a lagging peer can't resurrect it. Nodes pull missing chunks in the background from
  any peer that has them (`[replication] blob_bandwidth`, default 2 MB/s) and fetch a missing chunk at once when a reader
  asks for it (and keep it). `blob.get` on a blob the node hasn't heard of → `RETRY_LATER` (D32); on a deleted one →
  `NOT_FOUND`. Older peers ignore the new peer frames (requests time out after 10 s).
- **D46 Encryption and storage on the phone:** each blob has a random 32-byte key; ciphertext = Tink
  `AesGcmHkdfStreaming` (HMAC-SHA256, 32-byte keys, 1 MiB segments) with the blob key as associated data. The
  `Attachment` in the E2E content carries the key, the SHA-256 digest and size of the ciphertext, the dimensions and a
  ≤ 4 KiB thumbnail. The phone keeps the ciphertext file in `filesDir/media/` as the encrypted original (key in the
  SQLCipher DB); photos are decoded into memory only. "Очистить кэш" empties `cacheDir` (picker/camera copies) and the
  in-memory image cache; it never touches `filesDir/media/` (D24).
- **D47 Photo policy:** one photo per send; re-encoded as JPEG, long edge ≤ 2560 px, quality 85, orientation applied,
  **all metadata (EXIF, GPS) dropped**; inline thumbnail 64 px JPEG (≤ 4 KiB). Auto-download default: **Wi-Fi only**
  (unmetered network); options Wi-Fi / any network / manual. "Save to gallery automatically" default off. Typical photos
  become 0.3–3 MB, so the "20 MB" criterion is tested at the blob layer (meshsim + `LiveBlobTest`).
- **D48 Upload before envelope:** the PENDING message, its attachment and a **held** outbox row are written in one
  transaction; the envelope is released only after every chunk is on the node. Quota or invalid → the message becomes
  FAILED; "Повторить" re-publishes the blob under a new id. Node blobs are transient and are **not** part of node backups
  (`backup.sh` unchanged; D24: the phone's copy is the original).

**Tech Stack:** as M3 + `androidx.exifinterface` (orientation on API 26–27). Image decoding with `BitmapFactory`/`ImageDecoder`
and our own small loader (no Coil); zoom with Compose gestures (no extra library). Tink is already in `core:crypto` (1.19.0).

**Out of scope:** reply-quotes (no message has them yet; the photo menu has no «Ответить», same as text), several photos per
send, video/files/voice (D18), profile photos (need encrypted profiles, V2), push (M5), media in password backups (M6),
backup-kind blobs (M6 adds them), sharing photos to other apps, deleting originals in bulk.

**Branches:** `m4-photos` in `otter-server` and `otter-android` (from `main`). The top-level `docs/` is not in git; edit in place.

```go
func checkBlobMeta(b *pb.RecordBody) error {
	var m pb.BlobMeta
	if err := proto.Unmarshal(b.Payload, &m); err != nil {
		return ErrBadPayload
	}
	if m.Size == 0 || m.Size > MaxBlobSize || m.ChunkSize != BlobChunkSize {
		return ErrBadPayload
	}
	n := (m.Size + BlobChunkSize - 1) / BlobChunkSize
	if uint64(len(m.ChunkSha256)) != n {
		return ErrBadPayload
	}
	for _, h := range m.ChunkSha256 {
		if len(h) != 32 {
			return ErrBadPayload
		}
	}
	if len(m.Readers) == 0 || len(m.Readers) > MaxBlobReaders {
		return ErrBadPayload
	}
	seen := map[string]bool{}
	for _, r := range m.Readers {
		if len(r) != 16 || bytes.Equal(r, b.Author) || seen[string(r)] {
			return ErrBadPayload
		}
		seen[string(r)] = true
	}
	if b.ExpiresMs == 0 || b.ExpiresMs > b.CreatedMs+MaxBlobTTL.Milliseconds() {
		return ErrBadPayload
	}
	return nil
}
```

```go
// gcBlob deletes a blob whose readers all fetched it (or, with force, unconditionally) and tombstones its key (D45).
// Files are removed later by service.SweepBlobFiles.
func gcBlob(ctx context.Context, tx *sql.Tx, key []byte, force bool) error {
	var expires int64
	err := tx.QueryRowContext(ctx, `SELECT expires_ms FROM blobs WHERE blob_key=?`, key).Scan(&expires)
	if errors.Is(err, sql.ErrNoRows) {
		return nil
	}
	if err != nil {
		return err
	}
	if !force {
		var waiting int
		if err := tx.QueryRowContext(ctx, `SELECT COUNT(*) FROM blob_readers r WHERE r.blob_key=? AND NOT EXISTS
			(SELECT 1 FROM blob_fetched f WHERE f.blob_key=r.blob_key AND f.user_id=r.user_id)`, key).Scan(&waiting); err != nil {
			return err
		}
		if waiting > 0 {
			return nil
		}
	}
	for _, q := range []string{`DELETE FROM blobs WHERE blob_key=?`, `DELETE FROM blob_chunks WHERE blob_key=?`,
		`DELETE FROM blob_readers WHERE blob_key=?`, `DELETE FROM records WHERE record_key=?`} {
		if _, err := tx.ExecContext(ctx, q, key); err != nil {
			return err
		}
	}
	_, err = tx.ExecContext(ctx, `INSERT OR REPLACE INTO blob_tombstones(blob_key,until_ms) VALUES(?,?)`,
		key, expires+24*time.Hour.Milliseconds())
	return err
}
```

```kotlin
object BlobCipher {
    const val SEGMENT = 1 shl 20
    const val CHUNK = 256 * 1024
    data class Sealed(val size: Long, val sha256: ByteArray)

    fun newKey(): ByteArray = ByteArray(32).also { SecureRandom().nextBytes(it) }

    private fun aead(key: ByteArray) = AesGcmHkdfStreaming(key, "HmacSha256", 32, SEGMENT, 0)

    fun encrypt(input: InputStream, out: File, key: ByteArray, aad: ByteArray): Sealed {
        val md = MessageDigest.getInstance("SHA-256")
        DigestOutputStream(out.outputStream().buffered(), md).use { o ->
            aead(key).newEncryptingStream(o, aad).use { input.copyTo(it) }
        }
        return Sealed(out.length(), md.digest())
    }

    fun decrypt(file: File, key: ByteArray, aad: ByteArray): InputStream =
        aead(key).newDecryptingStream(file.inputStream().buffered(), aad)

    fun chunkHashes(file: File, chunk: Int = CHUNK): List<ByteArray> = file.inputStream().buffered().use { s ->
        val buf = ByteArray(chunk); val out = ArrayList<ByteArray>()
        while (true) {
            val n = s.readNBytes(buf, 0, chunk); if (n <= 0) break
            out += MessageDigest.getInstance("SHA-256").apply { update(buf, 0, n) }.digest()
        }
        out
    }
```

```kotlin
class PhotoPrep @Inject constructor() {
    data class Prepared(val jpeg: ByteArray, val width: Int, val height: Int, val thumb: ByteArray)
    class Unreadable : Exception()

    fun prepare(source: File, maxEdge: Int = 2560): Prepared {
        val bounds = BitmapFactory.Options().apply { inJustDecodeBounds = true }
        BitmapFactory.decodeFile(source.path, bounds)
        if (bounds.outWidth <= 0 || bounds.outHeight <= 0) throw Unreadable()
        var sample = 1
        while (max(bounds.outWidth, bounds.outHeight) / (sample * 2) >= maxEdge) sample *= 2
        val raw = BitmapFactory.decodeFile(source.path, BitmapFactory.Options().apply { inSampleSize = sample })
            ?: throw Unreadable()
        val rotated = rotate(raw, ExifInterface(source).rotationDegrees)
        val scaled = scaleDown(rotated, maxEdge)
        val jpeg = compress(scaled, 85)
        val thumb = thumbnail(scaled)
        return Prepared(jpeg, scaled.width, scaled.height, thumb)
    }
```

- [ ] **Step 1: `BlobMetaBuilder`** (pure, unit-tested):
```kotlin
object BlobMetaBuilder {
    const val TTL_MS = 30L * 24 * 3600 * 1000
    fun build(id: ByteArray, me: LocalAccount, file: File, readers: List<ByteArray>, now: Long): Record {
        val hashes = BlobCipher.chunkHashes(file)
        val meta = BlobMeta.newBuilder().setSize(file.length()).setChunkSize(BlobCipher.CHUNK)
            .addAllChunkSha256(hashes.map(::bs)).addAllReaders(readers.map(::bs)).build()
        return RecordCodec.sign(
            RecordCodec.body(RecordType.BLOB_META, me.userId, meta.toByteArray(), createdMs = now, id = id, expiresMs = now + TTL_MS),
            me.accountKey)
    }
    fun blobKey(author: ByteArray, id: ByteArray) = author + id
}
```
(If `RecordCodec.body` has no `id`/`expiresMs` parameters, add them with the current behaviour as defaults.)
- [ ] **Step 2: retry rule.** The ciphertext's aad is the original blob key, so a re-publish must keep that key: the
  re-signed `BLOB_META` uses the **same record id** with a new `created_ms`/`expires_ms`. Nodes dedup by record key, so this
  only works when the node never stored the old one (QUOTA, INVALID) — exactly the cases that lead to `UPLOAD_FAILED`. If
  the node answers `blobCreate` with OK for the old key (it was stored after all), continue uploading. If the old meta
  expired on the node (more than 30 days in UPLOADING — practically never), re-encrypt the original under a new key and id
  (the plaintext is recoverable from the file with the old key).

```kotlin
suspend fun run(api: NodeApi): Nothing {
    while (true) {
        drainOnce(api)
        val next = db.attachments().nextAttemptAt()
        val wait = if (next == null) Long.MAX_VALUE else (next - clock.now()).coerceAtLeast(0)
        withTimeoutOrNull(wait.coerceAtMost(60_000)) { kicks.receive() } // re-check auto-download each minute
    }
}
```
